# MVP implementation backlog

Proposal only. Application implementation starts only after product-owner review, one milestone at a time. Estimates are engineering hours including feature-specific tests/review, with optimistic–conservative ranges; they exclude legal/provider approval, external review delays and acquisition. A single experienced engineer at 30 productive hours/week needs approximately 36–67 weeks for 1,062–1,984 hours. Staffing can parallelize some work after domain foundations, but native/payment/security integration remains sequential. No commits/push/PR/deployment or paid infrastructure is authorized.

Source paths in the table are relative to the repository. “New” explicitly marks planned files. Complexity: M medium, H high, VH very high.

## Milestones and completion gates

M0 baseline/security: approved build repairs, supported toolchain decision, CI/tests and identity/resource isolation. Gate: API runs on SQL Server and unauthorized/cross-account operations fail; Android and iOS baseline builds on suitable runners. M1 pets: curated dog/cat/bird profiles, household and rehearsed dog migration. Gate: existing dog IDs/history preserved and owner-scoped dynamic profiles work. M2 bookable care: admin-reviewed capability evidence, deterministic eligibility, availability, quotes and multi-pet request/acceptance. Gate: all-animal qualification enforced and concurrent overlap requests cannot both succeed. M3 paid sandbox care: Connect, secure messaging/media, tasks/reports and operational admin. Gate: two cats + one bird complete the full sandbox flow with individual reports and replay/negative tests. M4 controlled paid launch: release/security/native/restore/operations approval and actual verification/insurance policies. Gate: jurisdiction/provider/payment policy approved and signed device/store builds validated; live commerce needs separate explicit approval.

## P1/P2 scope decisions

FWF-014 is P1 launch quality but mandatory before commercial launch, not optional safety. P1 launch polish is contained in task ranges: accessibility, proper empty/retry states, review eligibility/moderation basics, notification reliability and support observability. P2 separate, unestimated until approved: recurring-series scheduling, boarding/daycare expansion, additional species/habitat maintenance, grooming/training/transport referral policies, advanced caregiver analytics and SaaS team/subscription tools. No AI/social/livestream/white-label/farm/veterinary treatment in MVP.

## Test reporting contract

For every milestone publish commands, runner/project target, tests executed/passed/failed/skipped/blocked, fresh result paths and diagnosed defects. M0 adds unit + SQL integration + MAUI device harness; retain any subsequently added tests and thresholds. Required matrix: species validation/migration; cross-account isolation; all-pet eligibility; SQL concurrency; authoritative pricing; webhook signature/idempotency/order; cancellations; checklist auditing; authorized media; safe API errors; interrupted/offline sessions. Current audit: no existing test projects; no tests executed; API compile fails and mobile is blocked. Never describe scaffolds or a zero-test exit code as successful functionality.
